# КДЗ-2. Рациональные числа и дерево выражений

## 1. Почему иммутабельные операторы сделаны friend-функциями, а не методами класса? Что перестало бы компилироваться, если бы operator+ был методом?

Иммутабельные операторы мы реализуем как дружественные функции, чтобы можно было использовать операторы с разными типами аргументов, например:

```cpp
Fraction a(1, 2);
Fraction b = a + 2u;
Fraction b = 2u + a;
```
Если реализовать operator+ только как метод класса, выражение `2u + a` не скомпилируется, поскольку левый операнд типа uint32_t и у него нет метода operator+ для Fraction.

## 2. Почему мутабельные операторы возвращают ссылку, а иммутабельные - новый объект?

Мутабельные операторы (+=, -=, *=, /=) изменяют текущий объект, поэтому возвращают ссылку на него. Благодаря этому мы можем делать цепочки операций, например a += b += c;
Иммутабельные операторы (+, -, *, /) не изменяют исходные объекты, поэтому возвращают новый результат типа Fraction.

## 3. Что выведет std::cout << Fraction(1, 2) * -1; и почему? Какая перегрузка выбрана и по какому правилу overload resolution?

Выражение выведет:
4294967295/2

Это происходит потому, что оператор умножения принимает std::uint32_t, а литерал -1 имеет тип int. При неявном преобразовании отрицательного числа в беззнаковый тип оно преобразуется по модулю 2^{32}, поэтому -1 становится 4294967295.

В результате выполняется умножение:

1/2 * 4294967295

При выборе перегрузки компилятор рассматривает: operator*(const Fraction&, const Fraction&) (требует пользовательского преобразования) и operator*(const Fraction&, std::uint32_t) (требует стандартного преобразования из int в uint32_t). По правилам overload resolution, стандартное преобразование приоритетнее пользовательского. Поэтому будет выбрана перегрузка с std::uint32_t.

## 4. Как один operator<< для Expression печатает узлы разных типов?

Оператор << принимает ссылку на базовый класс Expression и вызывает виртуальную функцию print().
Из-за виртуального вызова выбирается реализация print() соответствующего объекта: Const, Negative, Add и т.д

## 5. Зачем Expression виртуальный деструктор?

Виртуальный деструктор необходим для правильного удаления объектов производных классов через указатель на базовый класс.

Если деструктор базового класса не будет виртуальным, удаление производного объекта через Expression* может привести к неопределённому поведению.

# Д.1. Упрощение выражений

Я реализовала функцию simplification, которая рекурсивно упрощает дерево выражений.

Использовала следующие правила:

1. Сворачивание констант: 2+3 -> 5
2. x+0 -> x, x-0 -> x
3. Сокращение противоположных: x+(-x) -> 0, x-x -> 0.
4. Умножение: x * 0 -> 0, x * (-1) -> -x, x * 1 -> x
5. Упрощение отрицания: -(-x) -> x.
6. Упрощение деления: 0/x -> 0 (если знаменатель не равен нулю), x/1 -> x.

Проверила все примеры в demo_expression.cpp (во всех случаях значения исходных и упрощённых выражений совпали, а количество операций после упрощения уменьшилось)
